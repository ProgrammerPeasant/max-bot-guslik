# festpass

Бот розыгрышей для мессенджера MAX. Фестиваль длится несколько дней, каждый день на сцену выходит
новый партнер: участник забирает его промокод, подписывается на канал, попадает в розыгрыш призов дня
и копит шансы на главный приз. Один активный день дает один шанс, максимум десять.

Внутри все устроено как на фестивале: афиша (`lineup.toml`) задает дни и партнеров, у каждого
участника есть пропуск с отметками о посещенных днях, а победители дня называются хедлайнерами.

## Что в нем необычного

**Честный жребий, который можно проверить.** Перед розыгрышем бот генерирует секретный ключ и сразу
показывает его отпечаток (sha256) в разделе «Правила акции». После розыгрыша ключ раскрывается в
выгрузке. Победители однозначно вычисляются из ключа и списка участников, так что любой может
пересчитать результат, а подменить ключ задним числом не выйдет: не сойдется отпечаток. Проверка
одной командой: `festbot verify <id>`.

Алгоритм умещается в несколько строк, его можно повторить без нашего кода:

```python
import hashlib

def ticket(seed, user_id, n):
    return int.from_bytes(hashlib.sha256(f"{seed}:{user_id}:{n}".encode()).digest(), "big")

def draw(seed, weights, places):
    best = {u: min(ticket(seed, u, n) for n in range(w)) for u, w in weights.items() if w > 0}
    return sorted(best, key=best.get)[:places]
```

Каждый шанс это билет. Участник идет в зачет с лучшим из своих билетов, поэтому семь активных дней
дают ровно в семь раз больше шансов, чем один, и при этом один человек не может занять два места.

**Тексты отдельно от кода.** Все, что видит участник, лежит в `texts.toml`. Редактор правит формулировки
и эмодзи, не трогая Python.

**Чат не превращается в ленту меню.** Навигация (меню, правила, «Мои шансы») редактирует то же
сообщение, а важное (промокод, заявка, приз) приходит новым сообщением и остается в истории.

**Время фестиваля, а не сервера.** День считается по часовому поясу из афиши, так что сервер в UTC
не перепутает партнеров после полуночи по Москве.

## Установка

```sh
python -m venv .venv
.venv/bin/pip install -e '.[dev]'
cp lineup.example.toml lineup.toml   # заполнить партнеров
export MAX_BOT_TOKEN=...             # токен бота из кабинета MAX для партнеров
```

Для проверки подписки бот должен быть **администратором канала каждого партнера**: MAX отдает
список участников канала только админам. `channel_id` в афише это id канала в MAX.

## День оператора

```sh
festbot seal                                  # перед стартом: опечатать все розыгрыши, опубликовать отпечатки
festbot promo 2026-09-01 codes/zerno.txt      # загрузить коды партнера (по одному в строке)
festbot run                                   # бот, крутится постоянно

# вечером, когда день закончился
festbot draw 2026-09-01                       # провести розыгрыш дня, прием заявок закрывается
festbot export 1                              # CSV для команды MAX и партнера
festbot confirm 1 --by "Ольга"                # без подтверждения уведомления не уйдут
festbot announce 1                            # уведомить победителей

festbot push --segment idle --text "Сегодня на сцене Вжух, загляни"
festbot stats --csv exports/stats.csv
```

После последнего дня: `festbot draw final`, `confirm`, `announce`. Победители финала получают кнопку
«Получить приз», оставляют имя и фамилию и дают согласие на передачу данных. Если победитель молчит
дольше `claim_hours` или заблокировал бота, приз переходит следующему резервному победителю. Бот
проверяет это сам раз в пять минут, вручную то же делает `festbot sweep`.

Сегменты рассылки: `all`, `active` (есть хотя бы один шанс), `idle` (сегодня еще ничего не сделали),
`day:2026-09-01` (участники розыгрыша этого дня). `--dry-run` только считает получателей.

## Статистика

`festbot stats` показывает по каждому дню: новых пользователей, запросы промокода, выданные коды,
остаток кодов, участников розыгрыша и активных участников. Ниже итоги: сколько всего людей запустили
бота, сколько его заблокировали и сколько набрали хотя бы один шанс.

## Устройство

| модуль | что делает |
|---|---|
| `config.py` | афиша и тексты |
| `store.py` | SQLite, все гонки закрыты транзакциями и уникальными индексами |
| `lots.py` | жребий |
| `bot.py` | сценарии диалога |
| `screens.py` | экраны: текст плюс кнопки |
| `desk.py` | проведение, подтверждение, проверка и выгрузка розыгрышей |
| `herald.py` | уведомления победителям, резервы, рассылки |
| `maxapi.py` | клиент MAX Bot API |
| `cli.py` | команда `festbot` |

Тесты: `.venv/bin/pytest`. Клиент MAX в тестах подменяется заглушкой, сценарии гоняются целиком,
от нажатия «Начать» до передачи приза резервному победителю.

## Что проверить перед запуском

- Базовый адрес API. В коде `https://platform-api.max.ru`, а свежая документация MAX
  (dev.max.ru/docs-api) рекомендует `platform-api2.max.ru`. Стоит сверить и поправить `API_URL`
  в `maxapi.py`.
- Метод `GET /chats/{chatId}/members?user_ids=...` в боевом канале партнера: прав администратора
  должно хватить, но лучше прогнать на тестовом канале.
- Срок `claim_hours` и формулировки в `texts.toml` должны совпадать с официальными правилами акции.
